# 闸对

中文名：**闸对** · 前缀 `gatetwin` · 端口 **6500 / 11500**

## 骨架

**刷卡点装载 → 同卡进站出站成对物化 → 缺腿/异向/超时旁路 → 行程账与刷卡点互证**

皮：地铁/公交闸机刷卡。去皮是 **OD 成对管道 + 开腿态 + 旁路 + 行程贯验**，不是票务售票 CRUD、不是乘车码业务页、不是日结封账。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6500
# 刷卡流 → 灌「成对样例」→ 看开腿账/行程账 → 再灌「缺腿超时样例」「出站孤儿样例」→ 行程贯验
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 刷卡点 | 带卡号/站点/方向/事件时的进出闸事件 |
| 开腿账 | 已进站尚未出站的在途开腿 |
| 行程账 | 进站+出站成对后的正式行程 |
| 旁路匣 | 缺腿超时 / 出站孤儿 / 重复进站等 |
| 行程贯验 | 成对刷卡 ↔ 行程笔数 ↔ 旁路命运互证 |

## 已落地邻题

### 进站无出强制结（闭站运营异常写闸）

全局口径（二选一的关键取舍，全局只此一种）：**虚出成对** —— 对指定在途开腿执行强制结时，同事务写「开腿已成对 + 虚出刷卡点 + 行程账 + 强制结账」，虚出可审计；未选「强制旁路无行程」。两口径差异（强制结后是否存在行程行、开腿是否仍在途）由只读接口的 `方式/行程键/valid` 显式区分。

- 写闸：`POST /api/强制结` `{开腿键, 操作员?, 原因?, 事件时?, 站点键?}` —— 同事务四写，任败整体回滚；同开腿重放幂等；非在途且无强制结记录 → 409。
- 只读：`GET /api/强制结[?开腿键=]` —— 开腿键、虚出或旁路、行程键、valid（跨账互证）。
- 互斥：强制结后真实出站 → 无在途开腿 → 出站孤儿旁路，不得第二行程；强制结与真实出站并发 → 开腿状态 CAS 裁决唯一胜者，不得双成对。
- 协同：强制结写闸 / 开腿账 / 刷卡点 / 行程账 / 旁路匣 / 行程贯验 / 开腿账页（在途腿可点「强制结」，下方列强制结记录）。
- 夹具：`强制结在途样例`（卡甲在途待结、卡乙超时旁路对照、卡丙正常成对）→ 对卡甲 `POST /api/强制结` → `强制结后再出站样例`（卡甲真实出站进旁路，无第二行程）→ 行程贯验对齐。
- 测试：`cd backend && python3 -m unittest tests.test_强制结 -v`（含强制结×出站并发不得双成对）。
